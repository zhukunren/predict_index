# 期权目录持续滞后导致发布阻塞的修复（2026-11-19）

当前应有交易日为 20261118，故障发布停在 20261117。修复后于上海时间 14:47:36 完成四模型计算，数据截止日恢复至 20261118；公开 HTTPS 健康、预测 JSON 和统计接口验证正常。重启后发布快照仍为 `20ee31ae-82f9-42d1-b0f9-b4a161d3eee1`，模型版本保持不变。

## 根因

前次修复增加全市场期权代码分类检查，但只依赖 Tushare 的合约基础信息。11 月 18 日挂牌的 10012843.SH—10012850.SH 已在日行情出现，Tushare `opt_basic` 的全目录、逐代码和上市日期查询均未收录。上交所官方挂牌记录证实这八份合约全部属于 510300（300ETF），生产模型使用 510050（50ETF）。因此无关标的目录持续晚到，也阻断了完整的 50ETF 预测批次。

故障初期还存在独立的上游基础行情空响应：取证时 26 次失败中，8 次为基础行情不可用，18 次为未知期权代码。基础行情后来恢复，期权目录缺失成为持续阻塞点。交易日历正确，定时重试持续执行，无停调度或模型版本漂移。

## 修改

- `prediction_service/option_directory.py`：Tushare 缺少身份时，先复用上一快照经过哈希校验的完整目录，再查上交所官方当日合约表；到期后需要补跑的合约还可查观察日对应的官方挂牌记录。严格核验代码、标的、认购认沽、首末交易日期、重复记录与分页总数。无法确定的代码仍拒绝发布，保留旧快照重试。
- `prediction_service/model_context.py`：保存官方原始目录、接收时间、查询标识与最终补全目录，并从已有清单校验后读取缓存。仅补缺失身份，既有 Tushare 记录及已发布日的冻结边界继续保持原值。
- `prediction_service/service.py`：行情拉取截止日不超过交易日历和发布时点所确定的应有日期，防止未到 18:30 的当日收盘数据阻塞此前交易日的补发。
- 冻结模型算法、模型包、阈值和行情数值来源未变；补全用到的八份 300ETF 合约不参与生产 50ETF 特征。
